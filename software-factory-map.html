How the software factory runs

Opus plans, Haiku builds, Sonnet tests, and one lead session moves the work between them. You give it a detailed brief and get back a tested feature branch, a pull request for a developer to review, and a report.

Inside one lane: when the loop stops

A lane takes one package at a time. Only critical and high bugs send work back to Haiku, so the loop can't run on forever chasing small issues.

What each lane costs the machine

Lanes run side by side because they share nothing that can collide. They also share as much as possible on disk, so a 1 GB node_modules doesn't become 8 GB.

The environment researcher measures one real lane, then sets the lane count:

lanes = min( available RAM ÷ measured lane RAM, free disk ÷ lane build cache )

The factory sets no limit on agents. It runs as many at once as the lanes support, so large builds use more lanes and more fix cycles.
